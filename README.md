# Literature & Regulation Tracker · Unified Knowledge Base

Continuous tracking across three areas — **Law** (data law · AI law), **Tech & Law**
(AI ethics / moral responsibility) and **Technology** (reinforcement learning / causal ML /
affective computing) — plus dedicated feeds for author **Yunyang Mo** and **Wuhan
University** (School of Law · School of Cyber Science and Engineering). Biweekly frontier topics.

**Live site:** https://landy-figer.github.io/lit-tracker/

> Note — the tracked literature itself is written in Chinese (Chinese legal texts and
> Chinese academic literature). Only this repository's documentation is in English.

## What is this

A **single-file static site** (`index.html` — self-contained, zero external dependencies,
no build step) that merges what used to be several separate entry points into one page,
with four modules switched by the top navigation:

| Module | Contents |
| --- | --- |
| 📚 Knowledge Base | Unified search and filtering over all 965 records (area / type / source / tag / journal / topic tree / year / starred), paginated 20 per page |
| 📰 Daily Digest | Every record added on a given ingest day (20 issues so far), sharing the same search / filter / pagination engine as the Knowledge Base |
| 🧭 Frontier | Biweekly research topics (2 issues): overview, key points, representative papers, tools |
| ℹ️ About | Statistics, data sources, the seven-part structured-abstract standard, run modes |

## Features

- **Full-text search** — multi-term AND with hit highlighting
- **Composable filters** — area × type (paper / law / news) × source × tag × journal × topic tree × year × starred
- **Real pagination** — 20 per page, page-number window + prev/next + jump to page
- **Seven-part structured abstracts** — every paper record follows
  *Positioning / Background / Contribution / Method / Experiments / Limitations / Implications*,
  fully expanded in the detail dialog
- **★ Starred** — mark one or many records, plus a one-click "starred only" view
- **Deep links** — `?q=<keyword>` straight to search, `#frontier` / `#about` straight to a
  module, `?issue=YYYY-MM-DD` straight to a digest issue

## Run modes

The page detects its runtime and adjusts what is available:

| | Local server mode | Static hosting mode (this repo / GitHub Pages) |
| --- | --- | --- |
| Search / filter / pagination / detail / journals / topic tree | ✅ | ✅ |
| Starred | ✅ saved to the database, syncs across devices | ✅ saved to browser `localStorage`; survives reloads, not synced |
| Edit / delete / PDF upload / re-classify | ✅ | ⛔ no backend — the controls hide themselves |
| Embedded PDF preview | ✅ | ⛔ hidden (PDFs are too large to ship in this repo) |

> Detection: a page opened from `file://` or `127.0.0.1` / `localhost` probes the local
> service at `/api/health`; every other origin (including GitHub Pages) is treated as
> static hosting right away, so no useless requests are made.

## Data sources

- **Papers** — arXiv (incremental API search, PDF-first), Crossref (journal / conference
  allow-list), CNKI (Chinese journals, added after manual search)
- **Law & news** — Chinese statutes and national standards, regulator announcements, public
  releases from the CAC / Supreme People's Court / EU, manually verified before ingest
- **Dedicated feeds** — author tracking for Yunyang Mo; institutional tracking for Wuhan
  University (School of Law · School of Cyber Science and Engineering)

## Deployment

The repository root is the site root and `index.html` is the only entry.

**Branch deployment — how this repo is published.** `Settings → Pages → Source: Deploy from
a branch → main / (root)`. Every push to `main` republishes the site automatically, so
updating the site is just: regenerate the bundle, commit, push.

An Actions-based workflow (`configure-pages` + `deploy-pages`) is also generated into the
publish bundle at `.github/workflows/pages.yml` as an optional alternative. It is **not
committed**, because GitHub only accepts workflow files from a token with the `workflow`
scope — paste it into the repository yourself if you prefer Actions deployment.

## Updating

The site is generated by the local tracker and synced here as a single file, no build step:

```
python tracker/publish_github.py     # one shot: regenerate -> stage -> commit -> push
```

or step by step:

```
python tracker/portal.py          # regenerate the unified site (index.html + reports/knowledge-portal.html)
python tracker/site_publish.py    # stage the publish bundle into _publish/
cd _publish
git add -A && git commit -m "Update site" && git push origin main
```

Pushing to `main` triggers a Pages rebuild, so the live site picks up the change within a
minute or two.
